## 2. Rationalization Rationale & Architecture

Prior to rationalization, configuration was fragmented across **14 distinct JSON and YAML files**, leading to several operational hazards:
1. **Config Drift & Redundancy**: Strategy parameters were duplicated across `defaults.json`, `mfs.json`, `defaults.india.json`, and `defaults.us.json`. Edits to one file were easily missed in others.
2. **Missing Comments**: Standard JSON does not support inline comments or documentation, making factor weight and gate rationales opaque.
3. **Pipeline Proliferation**: Separate pipeline files (`pipeline.yaml`, `pipeline_earlymb.yaml`, `pipeline_us.yaml`) repeated identical sync and backup stages with only strategy name differences.
4. **Scattered Metadata**: Domain knowledge (TAM estimates, thematic baskets, corporate governance alerts) lived in disconnected files that required ad-hoc Python loaders.

### The Unified Solution
1. **[`config/defaults.yaml`](file:///Users/raghavgarg/Projects/myGo/mycase/config/defaults.yaml)**: One human-readable, fully commented YAML file containing all factor score weights, Stage-1 hard filters, macro regime hurdles, market calendars, TAM data, and governance metrics.
2. **[`config/pipeline.yaml`](file:///Users/raghavgarg/Projects/myGo/mycase/config/pipeline.yaml)**: One parameterizable execution pipeline with runtime overrides (`--strategy`, `--index`, `--golden`).
3. **`data/backups/legacy_config/`**: Preservation of all historical JSONs for forensic audit and rollback safety.

## 3. Active Configuration Inventory

### 3.1 [`config/defaults.yaml`](file:///Users/raghavgarg/Projects/myGo/mycase/config/defaults.yaml)
- **Status:** `REQUIRED (PRIMARY MASTER CONFIG)`
- **Format:** YAML
- **Consumers:**
  - Go: [`pkg/config/defaults_yaml.go`](file:///Users/raghavgarg/Projects/myGo/mycase/pkg/config/defaults_yaml.go), [`pkg/stockpicker`](file:///Users/raghavgarg/Projects/myGo/mycase/pkg/stockpicker), [`pkg/marketcal`](file:///Users/raghavgarg/Projects/myGo/mycase/pkg/marketcal), [`cmd/`](file:///Users/raghavgarg/Projects/myGo/mycase/cmd/)
  - Python: [`scripts/update_sector_tam.py`](file:///Users/raghavgarg/Projects/myGo/mycase/scripts/update_sector_tam.py), [`scripts/check_customer_concentration.py`](file:///Users/raghavgarg/Projects/myGo/mycase/scripts/check_customer_concentration.py)
- **Sections**:
  1. `system`: General app name, version, and global defaults.
  2. `markets`: Settlement rules, timezones, and trading hours for `india` (NSE) and `us` (NYSE/NASDAQ). EOD settlement hour is anchored to `21:00` IST.
  3. `benchmarks`: Benchmark index mapping (`^NSEI`, `^CRSLDX`, `^GSPC`, `^RUT`).
  4. `strategies`:
     - `earlymb`: 4-Pillar institutional accumulation model (Composite RS 25%, VCP Tightness 25%, RVOL/Pocket Pivot 25%, Delivery Delta 25%) with Stage-1 hard filters and relief gates.
     - `multibagger`: Micro/Smallcap growth model (Piotroski, Revenue Growth, OPM, ROE, D/E).
     - `fairprice`: Graham/Lynch intrinsic value ensemble with margin-of-safety hurdles.
     - `value`: Deep value model (EV/EBITDA, P/B, FCF yield).
     - `us_quality_momentum`: US equity strategy (ROIC, Net Margin, Momentum 6M/12M, Low Beta).
     - `standard`: Baseline cross-sectional momentum model.
  5. `hysteresis`: Anti-churn parameters (`cooldown_days = 30`, `min_score_delta = 3.0`, `cooldown_bypass_rank = 3`).
  6. `sector_caps`: Risk diversification constraints (`max_stocks_per_sector = 3`, `max_sector_weight_pct = 25.0%`).
  7. `macro_regimes`: Macro multiplier thresholds for sizing hurdle rates.
  8. `themes`: Definitions of thematic model portfolios (`aitheme`, `microsmall`, `modularmicro`, `myall`, `hydrogen`).
  9. `tam`: Total Addressable Market estimates by sector/industry.
  10. `governance`: Red flags, auditor resignation alerts, and pledging limits.
  11. `customer_concentration`: Customer revenue concentration warning thresholds.

### 3.2 [`config/pipeline.yaml`](file:///Users/raghavgarg/Projects/myGo/mycase/config/pipeline.yaml)
- **Status:** `REQUIRED (PIPELINE MASTER CONFIG)`
- **Format:** YAML
- **Consumers:** [`cmd/pipeline.go`](file:///Users/raghavgarg/Projects/myGo/mycase/cmd/pipeline.go), [`pkg/pipeline`](file:///Users/raghavgarg/Projects/myGo/mycase/pkg/pipeline)
- **Description:** Unified execution pipeline that orchestrates:
  1. `sync`: Historical prices, delivery records, and quarterly fundamentals into `mycase.db`.

  4. `performance`: Benchmark attribution and CAGR calculations.
  5. `backup`: Timestamped backups of portfolio allocations.
- **Runtime Overrides:** Can be dynamically parameterized via CLI flags without modifying the file.

## 6. Execution Command Reference

With the rationalized configuration, commands use `config/defaults.yaml` automatically as the default configuration source:

### Early Multibagger (India - NSE)
```bash
# Standalone stock pick & Stage-1 screening:
mycase pick --index niftytotalmarket --method earlymb --top 20

# Point-in-Time Deep Analysis Report:
mycase pick --index niftytotalmarket --method earlymb --analysis

# Full automated pipeline execution:
mycase pipeline --config config/pipeline.yaml --strategy earlymb --golden data/microsmall.csv

# Fast execution without re-syncing upstream data:
mycase pipeline --exec-only --strategy earlymb
```

### Multibagger (India - Micro/Smallcap)
```bash
# Standalone stock pick:
mycase pick --index niftytotalmarket --method multibagger --top 20

# Pipeline execution:
mycase pipeline --config config/pipeline.yaml --strategy multibagger --golden data/microsmall.csv
```
